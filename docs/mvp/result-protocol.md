# Rust CLI result protocol, version 1

`run.json` is emitted by the Rust `ohos-pulse` CLI. It is distinct from the
historical Python feasibility formats. The CLI deserializes typed records and
validates acceptance-dependent requirements before writing JSON atomically.
Markdown is generated by re-reading that JSON. `ohos-pulse report` performs the
same validation before regenerating a summary; it never executes saved commands.

| Group | Contents |
|---|---|
| `schema_version` | Protocol version, currently 1 |
| `run` | Unique ID, UTC timestamp, CLI version, source commit/dirty state, CI run/attempt |
| `subject` | Fixture/scenario, executable kind, fixture/lockfile hashes, resolved libc version/features |
| `environment` | Host OS/architecture, required pins, rustc/Cargo identity, actual cargo-ohos/SDK metadata, provenance disclosure |
| `runtime_environment` | Null when unavailable; configured image reference/digest, observed guest identity and loader dependency resolution |
| `stages` | Exactly check, link, runtime and integration outcomes with reasons and command/assertion evidence |
| `artifact` | Relative executable path, SHA-256, architecture and ELF inspection command/logs, or null |
| `commands` | Argument vectors, status, host exit code, elapsed milliseconds and relative stdout/stderr paths |
| `cleanup` | Guest cleanup outcome; not_run when no unique directory was created |
| `diagnostics` | Errors retained in addition to stage outcomes |

Statuses are passed, failed, blocked, not_run, infra_error and timed_out. A timeout
records a null exit code when the deadline was exceeded; process termination is
not misreported as a guest assertion exit. The runtime stage records the actual
guest exit code separately from the hdc command exit. Image metadata describes the
expected provisioning profile; the local CLI does not verify that a connected
guest came from that archive. The workflow retains archive verification evidence.

A passing runtime requires successful link, guest identity, zero guest exit code,
a unique matching completion record, captured stdout/stderr and successful cleanup.
A failed guest scenario remains failed if later cleanup also fails; cleanup
infrastructure failure still takes precedence in the CLI exit code. A successful
assertion followed by cleanup failure retains its assertion fields and becomes
infra_error. Integration is always not_run in this implementation.

Paths to artifacts/logs must be nonempty relative paths with normal components.
The CLI verifies artifact bytes and containment before deployment. A separate
`runtime --build` execution copies build evidence into its own directory and
rebases references so moving the complete result does not break them. Original
command arguments are preserved, including the paths used during execution.

## Source identity

Fixture SHA-256 covers these sorted repository-relative paths and their bytes:

- fixtures/libc-file-io/Cargo.lock
- fixtures/libc-file-io/Cargo.toml
- fixtures/libc-file-io/src/main.rs

Each path and file content is preceded by its byte length as an unsigned 64-bit
big-endian integer. This avoids ambiguous concatenation. Lockfile SHA-256 hashes
its raw bytes independently. Snapshots of these inputs are retained for every run.
A dirty checkout also retains tracked changes via `git diff HEAD --binary`; the
fixture snapshot identifies untracked fixture content. The report is evidence for
the snapshotted fixture, not an archive of all untracked repository files.

The actual dependency version and features come from locked Cargo metadata.
Required Rust, cargo-ohos and SDK identities are checked before target compilation.
The reviewed target and fixture are fixed; configuration does not execute commands.

## Limits

This is the initial implemented protocol; a standalone JSON Schema is not yet
provided. Typed deserialization and semantic validation are used by the CLI.
Unavailable runtime metadata stays null. SDK archive digest/attestation verification
remains an open issue. No cross-run aggregation or database importer is implemented.
Logs and binaries uploaded to GitHub Actions expire after 14 days.
